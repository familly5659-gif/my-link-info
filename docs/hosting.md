# eco.log94 공개 운영

## 현재 Codespaces 주소

Codespaces의 **포트 → 공개 범위(Port Visibility) → Public** 설정으로 실행 중인 페이지를 공유할 수 있습니다. 비공개 포트는 GitHub 인증이 필요하며 다른 사람이 열지 못할 수 있습니다. 공개로 바꾸기 전에 관리자 키는 공유하지 마세요. 상품 조회는 공개되지만 상품 추가·수정·삭제 API에는 관리자 키가 필요합니다.

Codespaces가 중지되거나 서버 프로세스가 종료되면 페이지에 접속할 수 없습니다. 개발용 Codespaces 주소는 상시 운영용으로 사용하지 마세요.

## Render 상시 운영 설정

저장소의 `render.yaml`은 다음 리소스를 준비합니다. 파일을 GitHub에 올리는 것만으로 리소스가 생성되거나 요금이 발생하지 않습니다.

- 절전 없이 실행하는 **유료 Starter 웹 서비스**
- SQLite 상품 DB와 썸네일 캐시를 보존하는 **유료 1GB 영구 디스크**
- Render가 관리하는 공개 HTTPS 주소
- 자동 생성되는 관리자 키 `ADMIN_KEY`
- `/api/status` 상태 확인
- GitHub 커밋마다 운영 서비스가 재시작되지 않도록 자동 배포 비활성화

**주의:** 현재 가격과 예상 월 요금은 Render의 생성 화면에서 확인하고 결정하세요. 무료 인스턴스는 절전과 영구 저장 제한 때문에 이 설정에 사용하지 않습니다. 영구 디스크를 붙인 Render 서비스는 배포할 때 기존 인스턴스를 멈추고 교체하므로 몇 초간 접속이 끊길 수 있습니다. ‘한 번도 끊기지 않는 운영’을 보장하는 설정은 아닙니다. 배포 중에도 연속 접속이 필요하면 외부 DB와 여러 인스턴스를 사용하는 구조로 별도 전환해야 합니다.

### 생성 순서

1. [Render](https://render.com)에 로그인하고 GitHub를 연결합니다.
2. **New → Blueprint**에서 이 GitHub 저장소와 `main` 브랜치를 선택합니다.
3. `render.yaml`의 유료 서버·디스크와 예상 비용을 검토한 뒤, 사용하기로 결정했을 때 생성합니다.
4. 배포 상태가 **Live**가 되면 서비스 화면에 표시된 공개 HTTPS 주소를 엽니다. 실제 주소는 Render에서 할당하며 미리 확정하지 않습니다.
5. GitHub에 로그인하지 않은 브라우저/시크릿 창과 휴대폰에서 상품 검색과 링크 열기를 확인합니다.
6. Render 서비스의 **Environment**에서 `ADMIN_KEY`를 비공개로 확인하고 관리자 로그인에 사용합니다. 이 값은 GitHub·채팅·공개 로그에 올리지 마세요.
7. 코드 변경 후에는 Render의 수동 배포 기능으로 새 버전을 배포합니다. 자동 배포를 꺼 둔 상태에서는 `git push`만으로 운영 사이트가 바뀌지 않습니다.

`PORT`는 Render가 공급하는 값을 그대로 사용합니다. `HOST=0.0.0.0`으로 외부 요청을 받고 `DATA_DIR=/var/data/eco-log94`에 데이터를 저장합니다. 데이터 경로를 임시 파일 시스템이나 저장소 내부로 바꾸지 마세요.

### 기존 상품 데이터 이전

Codespaces와 Render는 서로 다른 컴퓨터입니다. GitHub에 코드를 올려도 Codespaces의 `.data/links.sqlite`와 상품 데이터는 자동으로 Render에 복사되지 않습니다.

상품 수가 적으면 공개 운영 서버에서 관리자 로그인 후 다시 등록할 수 있습니다. DB를 그대로 이전하려면 원본 서버를 중지하거나 SQLite의 온라인 백업 기능으로 일관된 백업본을 만든 뒤, 운영 서버의 영구 디스크에 복원하는 별도 이전 작업이 필요합니다. `links.sqlite` 파일만 운영 중에 복사하면 WAL에 남은 변경이 누락될 수 있습니다. `.data/admin-key`, DB 및 백업 파일을 공개 GitHub에 커밋하지 마세요.

실제 데이터 이전, Render 계정 연결, 유료 리소스 생성, 공개 주소 발급과 외부 접속 검증은 설정 파일 준비와 구분해서 수행해야 합니다.

### 운영 확인

- 공개 주소의 첫 화면이 정상 로드되고 검색·카테고리·상품 링크가 작동하는지 확인합니다.
- 로그아웃 상태에서 상품 조회가 가능하고 수정·삭제는 허용되지 않는지 확인합니다.
- 관리자 로그인으로 임시 상품을 등록하고 Render 서비스를 재시작한 뒤 남아 있는지 확인합니다. 확인 후 임시 상품만 삭제합니다.
- 상태 확인 경로 `/api/status`가 HTTP 200을 반환하는지 확인합니다.
- 서비스 제공자의 장애나 네트워크 장애 가능성은 남습니다. 자체 도메인은 서비스의 Custom Domains에서 추가할 수 있습니다.
